# 2026-09-12 — OpenShift etcd Disaster Recovery

## Incident

MedusaLab experienced an unexpected power outage that left the OpenShift
control plane without etcd quorum.

The existing etcd state was preserved and a previously validated backup from
August 30, 2026 was used for recovery.

## Recovery

- Restored the etcd snapshot on `ocp-cp01`.
- Verified the restored single-member etcd cluster.
- Confirmed the Kubernetes API became available.
- Temporarily disabled the etcd Operator quorum guard using the documented
  OpenShift recovery override.
- Powered on `ocp-cp02` while `ocp-cp03` remained offline.
- Allowed the etcd Operator to reconstruct the cp02 etcd member.
- Verified two-member etcd health.
- Powered on `ocp-cp03`.
- Allowed the etcd Operator to reconstruct the cp03 etcd member.
- Verified all three etcd members were healthy and committing proposals.
- Confirmed all three OpenShift nodes returned to `Ready`.
- Confirmed the etcd ClusterOperator was:
  - `Available=True`
  - `Progressing=False`
  - `Degraded=False`
- Removed the temporary unsupported recovery override.
- Reverified etcd health after normal quorum protection was restored.

## Final Validation

- All three nodes are `Ready`.
- All ClusterOperators are healthy.
- No failed or incomplete pods remain.
- OpenShift API access through HAProxy works.
- OpenShift Console route returns HTTP 200.
- Ingress canary returns `Healthcheck requested`.
- DO180 nginx application route returns HTTP 200.
